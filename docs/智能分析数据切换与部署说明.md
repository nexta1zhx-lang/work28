> 适用系统：TXYK（体系运控分系统，Vue 2 + vue-cli + Element UI）
> 更新日期：2026-08-25

---

## 一、智能分析两个界面的「模拟数据 / 真实 URL」切换

### 1.1 涉及的两个界面

| 界面         | 路由                          | 组件文件                                          |
| ------------ | ----------------------------- | ------------------------------------------------- |
| 任务网可视化 | `/task-network-visualization` | `src/views/system-cloud/TaskNetVisualization.vue` |
| 事中规划     | `/in-process-planning`        | `src/views/system-cloud/InProcessPlanning.vue`    |

这两个页面有**两种数据来源**：

- **本地模拟（mock）**：使用 `src/views/system-cloud/mockData.js` 生成的假数据，自绘 ECharts 图表，**不依赖任何外部服务**。
- **真实服务（real）**：通过 POST 请求真实服务接口，把服务端返回的 HTML 页面用 `iframe.srcdoc` 嵌入展示。

### 1.2 切换开关（env 变量）

在 `.env.development`（开发） / `.env.production`（生产）中配置。这些变量是**构建期**读取的，改动后需**重启 dev server**（开发）或**重新 build**（生产）才生效。

| 变量                      | 取值             | 作用                                                                                                                                                 |
| ------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VUE_APP_MOCK_ANALYSIS`   | `true` / `false` | `true` = 菜单显示「任务网可视化 + 事中规划」并隐藏原三个模块；`false` = 菜单显示原业务模块（作战筹划信息 / 数据链保障需求分析 / 数据链保障方案构建） |
| `VUE_APP_ANALYSIS_SOURCE` | `mock` / `real`  | `mock` = 两个分析页用本地模拟数据；`real` = 对接真实服务 URL                                                                                         |
| `VUE_APP_ANALYSIS_SERVER` | 服务地址         | `real` 模式下的真实服务基址，如 `http://39.101.73.142:8090`                                                                                          |

### 1.3 常见切换场景

| 场景                    | `VUE_APP_MOCK_ANALYSIS` | `VUE_APP_ANALYSIS_SOURCE` | 效果                                         |
| ----------------------- | ----------------------- | ------------------------- | -------------------------------------------- |
| 演示 / 联调（模拟数据） | `true`                  | `mock`                    | 菜单显示两个分析页，展示本地模拟图表         |
| 对接真实服务            | `true`                  | `real`                    | 菜单显示两个分析页，iframe 嵌入真实服务 HTML |
| 恢复原业务模块          | `false`                 | 任意                      | 菜单恢复「作战筹划信息」等三个原模块         |

### 1.4 切换操作步骤

1. 编辑 `.env.development`（开发）或 `.env.production`（生产）中的变量。
2. **开发**：重启 dev server —— 停掉当前的 `npm run serve` 后重新运行 `npm run serve`。
   **生产**：重新执行 `npm run build` 并把 `dist/` 重新部署。
3. 打开页面：右上角有**「本地模拟」/「真实服务」**标签，状态栏显示数据来源与服务地址，可直观确认当前处于哪种模式。

### 1.5 真实服务模式说明

- 接口均为 **POST**，请求体 JSON 带 `input_json` 字段（接口输入 JSON 的完整字符串）：
  - 任务网可视化：`POST {SERVER}/api/visual/`（`input_json` 必填）
  - 事中规划：`POST {SERVER}/api/in-process/page`（`input_json` 可不传，不传用服务器当前数据）
- 两个页面默认传给服务的 `input_json` 定义在 `src/views/system-cloud/analysisConfig.js`（`defaultVisualInput()` / `defaultInProcessInput()`），可按需修改。
- 服务端 CORS 已放开，可跨域直调；**若前端是 HTTPS，真实服务也必须是 HTTPS**，否则浏览器拦截。
- iframe **不要加 sandbox**，否则页面脚本无法运行。
- 相关代码：
  - `src/views/system-cloud/analysisConfig.js`：读取 env（`ANALYSIS_REAL` / `ANALYSIS_SERVER`），`loadRealPage()` 实现 POST → 补 `<base>` → `iframe.srcdoc`。
  - 两个页面：`useReal` 为 `true` 时走 iframe 分支（`v-else`），`false` 时走本地 mock 分支（`v-if="!useReal"`）。

## 二、前端部署

> 本文档只描述**前端（Vue 单页应用）**的部署。后端服务、达梦数据库的部署不在本文范围。

### 2.1 构建

1. 配置 `.env.production`（构建期生效）：
   - `VUE_APP_BASE_API`：后端接口地址（留空表示同源，由部署服务器反代到后端）
   - `VUE_APP_MOCK_ANALYSIS`、`VUE_APP_ANALYSIS_SOURCE`、`VUE_APP_ANALYSIS_SERVER`：见第一章
2. 安装依赖并构建：

   ```bash
   npm install
   npm run build          # 生成 dist/（方案A：不含瓦片，构建快、内存低）
   # npm run build:full   # 方案B：瓦片也复制进 dist/，整目录部署
   ```

   构建产物为 `dist/` 静态目录。默认（方案A）**不含瓦片**，瓦片由 Nginx 单独托管（见 2.2 / 2.3）；
   用 `build:full`（方案B）则含瓦片，可整目录部署到任意静态服务器（Nginx / IIS / 对象存储等）。

### 2.2 部署到 Nginx（推荐，含缓存加速）

推荐直接用仓库里的现成文件 **`deploy/nginx.conf`** —— 完整、可直接放服务器使用。部署三步：

```bash
# 1) 构建前端（方案A：dist/ 不含瓦片）
npm install && npm run build
# 2) 上传前端 + 瓦片到服务器
rsync -av dist/       /data/txyk/dist/
rsync -av tiles-data/ /data/tiles/    # 内部结构 /data/tiles/sat/{z}/{x}/{y}.jpg
# 3) 启用配置（按服务器实际改 server_name / root / 瓦片路径 / 后端地址，见文件内 TODO）
cp deploy/nginx.conf /etc/nginx/conf.d/txyk.conf
nginx -t && nginx -s reload
```

与旧版的关键差异：**瓦片已从 `public/` 移出**（见 2.3），生产由 Nginx 用 `alias` 直接托管瓦片数据目录（方案A），不再依赖 dist 内的拷贝：

```nginx
root /data/txyk/dist;                       # 前端 dist（不含瓦片）
location / { try_files $uri $uri/ /index.html; }

# 瓦片 URL 不变，alias 指向独立数据目录（缓存 1 年 immutable）
location /sat/    { alias /data/tiles/sat/;    expires 1y; add_header Cache-Control "public, max-age=31536000, immutable"; access_log off; }
location /sat_gd/ { alias /data/tiles/sat_gd/; expires 1y; add_header Cache-Control "public, max-age=31536000, immutable"; access_log off; }
```

> 若部署环境无法用 Nginx（如 IIS / 对象存储），改用方案B：`npm run build:full`，瓦片随 `dist/` 一起发布，任意静态服务器均可整目录托管（此时删除上面两个 `alias` location）。

**缓存加速要点说明**

- **瓦片/静态资源设长缓存**：`sat`、`sat_gd` 瓦片和构建产物 `js/css` 都是不变文件，`Cache-Control: immutable` 后**第二次访问几乎零请求**（直接从浏览器缓存读取）。瓦片平均 9KB、量又大，缓存收益最大。
- **gzip 压缩文本**：`world-countries-detail.geojson`（2.9MB 文本）压缩后可降到几百 KB；jpg 已是压缩格式，不需要也不建议再压。
- **`index.html` 不缓存**：保证每次刷新都能拿到最新的页面壳（否则改版后用户拿旧页面）。
- **HTTP/2（可选升级）**：上面是 HTTP 直连。想进一步提速可上 HTTPS + HTTP/2（一个连接并发传多个小瓦片，对瓦片这种「多而小」的请求提升明显），只需把监听改成 `listen 443 ssl http2;` 并配置证书（如 `ssl_certificate` / `ssl_certificate_key`），缓存配置不变。

> 关键点：本项目是 **history 路由**，`location /` 必须配置 `try_files $uri $uri/ /index.html`，否则刷新页面或直接访问子路径会 404。

### 2.3 GIS 图片（离线瓦片 / GeoJSON）怎么用

本系统的「轻量 GIS 点位展示」等地图页面**完全离线**，不依赖在线地图服务。

> **2026-08-25 变更**：瓦片已从 `public/` 移出到项目根目录 `tiles-data/`（已 gitignore）。
> 原因：`sat` + `sat_gd` 共约 5.8 万个文件（约 360 MB），放在 `public/` 会被 copy-webpack-plugin 全部读进内存，
> 导致构建在 `sealing (asset processing copy-webpack-plugin)` 阶段 **OOM（JS heap out of memory）**，小内存/旧 Node 机器上必现。
> 移出后：**开发**由 `scripts/serve-tiles.js` 提供；**生产**由 Nginx 托管（方案A）；也可 `npm run build:full` 打进 dist（方案B）。

| 目录 / 文件                                    | 内容                  | 大小     | 前端引用方式                               | 生产来源（方案A）                     |
| ---------------------------------------------- | --------------------- | -------- | ------------------------------------------ | ------------------------------------- |
| `tiles-data/sat/{z}/{x}/{y}.jpg`               | Esri 卫星影像离线瓦片 | ≈ 210 MB | `L.tileLayer('/sat/{z}/{x}/{y}.jpg')`      | Nginx `alias` → `/data/tiles/sat/`    |
| `tiles-data/sat_gd/{z}/{x}/{y}.jpg`            | 高德影像离线瓦片      | ≈ 150 MB | `L.tileLayer('/sat_gd/{z}/{x}/{y}.jpg')`   | Nginx `alias` → `/data/tiles/sat_gd/` |
| `public/md/geo/world-countries.geojson`        | 世界国家边界          | 251 KB   | `fetch('/md/geo/world-countries.geojson')` | 仍在 `dist/` 内（随前端发布）         |
| `public/md/geo/world-countries-detail.geojson` | 世界国家边界（精细）  | 2.9 MB   | 同上（更细粒度图层）                       | 同上                                  |
| `public/md/geo/coastline.geojson`              | 海岸线                | 1.6 MB   | 同上（海岸线图层）                         | 同上                                  |

使用说明：

- **开发**：开两个终端 —— `npm run serve:tiles`（瓦片服务，端口 8090）+ `npm run serve`。
  `vue.config.js` 里 `/sat`、`/sat_gd` 已配置代理转发到 8090，前端代码**零改动**。
- **生产（方案A，推荐）**：Nginx 用 `alias` 直接托管 `tiles-data/`（见 `deploy/nginx.conf`），URL 不变。
  ```bash
  rsync -av tiles-data/ /data/tiles/
  ```
- **生产（方案B，备选）**：`npm run build:full`，构建后把瓦片复制进 `dist/`，任意静态服务器均可整目录部署。
- 地图页面（`src/views/system-operations/yktsjs/LeafletGisView.vue`）用 Leaflet 加载：
  - 瓦片：`L.tileLayer('/sat/{z}/{x}/{y}.jpg?v=5')` —— 浏览器直接向部署服务器请求；
  - 边界：`fetch('/md/geo/world-countries.geojson')` 等拉取 GeoJSON 后叠加（GeoJSON 仍在 `public/`，随 dist 发布）。
- 部署后验证：浏览器直接访问 `http://<你的域名>/sat/2/0/0.jpg` 能看到图片、`/md/geo/world-countries.geojson` 能下载。
- **切换 Esri / 高德瓦片**：LeafletGisView 页面内有开关（`/sat` ↔ `/sat_gd`），切换即可换底图。
- **体积注意**：方案A 下 `dist/` 不再含瓦片（体积大幅减小，上传快）；瓦片约 360 MB 由服务器磁盘承载，浏览器按需请求。若对存储/带宽敏感，可只保留一种瓦片。

### 2.4 常见问题排查

| 现象                     | 排查方向                                                                                                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 刷新页面 / 直链访问 404  | history 路由未配 `try_files $uri $uri/ /index.html`                                                                                                                                    |
| 登录/接口失败            | `/rest` 代理是否配置、后端是否可达                                                                                                                                                     |
| GIS 地图空白             | 开发：`npm run serve:tiles` 是否在跑（8090 可达）；生产：`/sat`、`/sat_gd` 的 Nginx alias 路径是否正确、`/data/tiles/` 是否已 rsync；F12 看 `/sat/...jpg` 是否 404、GeoJSON 是否可访问 |
| 智能分析真实服务加载失败 | 见第一章 1.5：服务地址、CORS、HTTPS 一致性                                                                                                                                             |
